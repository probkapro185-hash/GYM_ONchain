# Исправления по результатам проверки SFEDU

Исправлены все 14 групп ошибок из отчёта и четыре дополнительные несогласованности интерфейса.

| Проблема | Что изменено |
| --- | --- |
| Сборка и проверки | Восстановлены зависимости Go; исправлены типы ID, проверка safety identifier и имена таблиц в тестах. |
| Первый администратор | Собственный ADMIN_EMAIL обновляет заготовку администратора без конфликта уникального телефона. Инициализация выполняется в транзакции с блокировкой. |
| Почта в Docker | В контейнер передаются MAIL_MODE, APP_BASE_URL, TTL и все SMTP-параметры. |
| Потеря выбранного тренера | trainer_id сохраняется в заявке и переносится в занятие; менеджер может заменить тренера или выбрать занятие без тренера. |
| Календарь | Переходы дня/недели/месяца загружают нужный диапазон; клиент открывает свой календарь; устаревшие ответы не перезаписывают новый период. |
| Состояние абонементов | Профиль, оплаты и CRM различают активные, замороженные, истёкшие, будущие и исчерпанные абонементы. Замороженные исключены из активного контекста AI и списка клиентов. |
| Чужие задачи | Изменение задачи менеджером ограничено исполнителем в самом SQL-запросе; администратор сохраняет полный доступ. Исправлена также обнаруженная при проверке SQL-ошибка типов параметра статуса. |
| Обход активации | Прямое создание client через POST /users запрещено; клиент создаётся через приглашение или одобрение заявки и сам устанавливает пароль. |
| Несколько абонементов | При заполнении одного выбирается следующий с доступными занятиями. Перенос не учитывает собственную бронь второй раз. |
| Фото тренеров | Создан доступный для записи каталог и постоянный Docker volume; CSP разрешает blob-превью. |
| CSV | Выводятся числа вместо адресов указателей; безлимит и отсутствующие измерения имеют понятные обозначения. |
| Первое подтверждение записи | Оповещение отслеживает изменение статуса заявки, включая переход от нуля подтверждений к одному; не повторяется при каждом опросе. |
| Устаревшие данные клиентов | Убран кеш списка пользователей: баланс, активация, посещения и остаток занятий читаются из БД. |
| Статистика посещений | Недельный запрос охватывает понедельник; последнее посещение хранит дату тренировки и не сдвигается назад при внесении старого визита. |
| Дополнительные замечания | Экспорт общего списка скрыт у менеджера; тип абонемента выбирается и сохраняется; администратор может восстановить тренера; пол клиента передаётся из заявки. |

## Обновление установленного проекта

В Docker выполните `docker compose up --build -d`. Приложение само применяет миграцию `000012_review_fixes`. При локальном запуске пересоберите/перезапустите Go-сервер. Файл `.env` не изменён: для настоящей почты в нём должны быть настроены SMTP и публичный APP_BASE_URL.

Миграция пересчитывает last_visit_at для клиентов с завершёнными тренировками. Старые заявки не получают выдуманные значения пола или тренера: их уточняет сотрудник при одобрении. Уже созданные ранее активные аккаунты не блокируются задним числом.

## Повторяемые проверки

```bash
make test-all test-race
# Только на отдельной тестовой базе с применёнными миграциями:
TEST_DATABASE_URL='postgres://…' make integration
```

Добавлены 8 поведенческих тестов интерфейса, проверки bootstrap, запрета обхода активации, прав на задачи, сохранения тренера, пола и CSV. Интеграционный сценарий проверяет резервирование нескольких абонементов, перенос занятия, сохранение тренера, восстановление его карточки, задачи разных менеджеров, исторические визиты, заморозку и разморозку. Данные сценария откатываются транзакцией.
